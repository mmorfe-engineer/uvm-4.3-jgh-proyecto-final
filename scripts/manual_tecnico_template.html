3. Arquitectura Full-Stack Monorepo

El sistema se estructura mediante un patrón Monorepo con desacoplamiento funcional completo entre la capa de presentación (Frontend SPA) y la capa de servicios de datos (Backend RESTful API). La comunicación entre capas se realiza estrictamente a través de peticiones HTTP/JSON autenticadas mediante cookies de sesión HttpOnly.

5. Modelo de Datos NoSQL y Esquemas Mongoose

La persistencia se implementa sobre MongoDB utilizando Mongoose ODM. El esquema documental garantiza tipos estrictos, sanitización y restricciones de unicidad.

5.1. Esquema de Usuario (users)

const userSchema = new mongoose.Schema({
  name: { type: String, required: true, trim: true, maxlength: 100 },
  email: { type: String, required: true, unique: true, lowercase: true, trim: true },
  passwordHash: { type: String, required: true, select: false }, // Nunca expuesto en JSON
  role: { type: String, enum: ['admin', 'participant'], default: 'participant' },
}, { timestamps: true });

5.2. Esquema de Encuesta Formativa (surveys)

  required: { type: Boolean, default: true },
  options: { type: [String], default: [] },
}, { _id: false });

const surveySchema = new mongoose.Schema({
  title: { type: String, required: true, trim: true, maxlength: 200 },

6. Catálogo de la API RESTful y Contratos OpenAPI 3.1

El backend expone una interfaz RESTful estructurada por recursos bajo el prefijo /api. Todas las respuestas de error retornan un formato homogéneo con código de estado HTTP adecuado y mensaje explicativo.

Método Endpoint Nivel de Acceso Descripción y Contrato
GET /api/health Público Estado de conectividad del backend y MongoDB (status 200 o 503).
GET /api/openapi.json Público Entrega de la especificación OpenAPI 3.1 descargable para clientes Swagger/Postman.
POST /api/auth/register Público Registro de participante. Fuerza incondicionalmente el rol participant.
POST /api/auth/login Público Inicio de sesión verificando Bcrypt y emitiendo cookie HttpOnly connect.sid.
POST /api/auth/logout Sesión Destruye la sesión en MongoDB e invalida la cookie del navegador.
GET /api/auth/me Sesión Retorna los datos del usuario en sesión activa sin exponer el password hash.
GET /api/surveys Público / Sesión Filtro de encuestas. Para visitantes solo muestra encuestas en estado published.
GET /api/surveys/:id Público / Sesión Retorna detalle de encuesta. Rechaza borradores a participantes no autorizados (403).
POST /api/surveys Admin Crea una nueva encuesta formativa en estado borrador inicial (draft).
PATCH /api/surveys/:id Admin Modifica o publica una encuesta. Exige que tenga preguntas válidas para publicar.
POST /api/contact Público Recibe formulario multipart con los 5 campos normativos y valida archivo adjunto.
GET /api/contact/admin Admin Lista las solicitudes de contacto recibidas para gestión y coordinación institucional.
GET /api/contact/admin/:id/attachment Admin Descarga segura del archivo físico adjunto con prevención de path traversal.
Contrato Reservado para morfemartin: Las rutas POST /api/surveys/:id/responses, GET /api/me/responses y GET /api/admin/surveys/:id/responses se encuentran documentadas en el contrato de integración formal para su incorporación mediante Pull Request.

7. Seguridad, Control de Acceso y Gestión de Archivos

El sistema implementa defensas en profundidad proporcionales al alcance del proyecto, evitando el almacenamiento inseguro de tokens en el cliente y validando rigurosamente cada carga de información.

7.1. Autenticación y Sesiones HttpOnly

  • Protección contra XSS: No se utilizan tokens JWT guardados en localStorage o sessionStorage. Las credenciales de sesión se transmiten a través de la cookie connect.sid con la directiva HttpOnly: true, haciendo inaccesible la sesión para scripts inyectados.
  • Hashing Criptográfico: Las contraseñas se procesan mediante bcryptjs con factor de coste 10 antes del guardado. El método toJSON() de Mongoose elimina explícitamente passwordHash de toda serialización.
  • Persistencia de Sesiones: Las sesiones se almacenan en MongoDB mediante connect-mongo con un tiempo de vida (TTL) de 7 días.

7.2. Autorización Basada en Roles (RBAC)

const requireRole = (...allowedRoles) => (req, res, next) => {
  if (!req.user || !allowedRoles.includes(req.user.role)) {
    return res.status(403).json({
      error: 'Acceso prohibido',
      message: 'Permisos insuficientes para realizar esta acción.'
    });
  }
  next();
};

7.3. Subida Segura de Archivos Multipart

El endpoint de contacto procesa archivos mediante multer aplicando cuatro capas de verificación:

  1. Restricción de Tamaño: Límite máximo de 3 MB por archivo (fileSize: 3 * 1024 * 1024).
  2. Filtro MIME Estricto: Se rechazan formatos ejecutables (.exe, .sh, .bat). Solo se autorizan application/pdf, image/png y image/jpeg.
  3. Nombres de Almacenamiento Aleatorios: El archivo se renombra en disco como \${Date.now()}-\${uuidv4()}\${ext}, imposibilitando colisiones o sobreescritura accidental.
  4. Prevención de Path Traversal: Los archivos se guardan fuera del árbol público en backend/uploads/. La descarga administrativa verifica que la ruta resuelta pertenezca estrictamente al directorio de subidas.

9. Formulario de Contacto y Solicitudes Formativas

El formulario de contacto constituye un requerimiento central del pliego oficial de la E-Actividad 4.3, exigiendo un mínimo de cinco campos de tipos distintos. La solución implementada integra ocho campos funcionales con validación reactiva en tiempo real y persistencia en MongoDB.

Campo del Formulario Tipo HTML Tipo Normativo Exigido Reglas de Validación Aplicadas
Nombre Completo text Texto Obligatorio, sin espacios vacíos, máximo 100 caracteres.
Correo Electrónico email email Obligatorio, sintaxis RFC 5322 verificada (^\S+@\S+\.\S+$).
Teléfono de Contacto tel phone Obligatorio, mínimo 7 dígitos numéricos válidos.
Fecha Propuesta date date Obligatoria, fecha válida para la realización de la actividad.
Participantes Estimados number number Obligatorio, entero estrictamente mayor a 0 y menor a 5000.
Tipo de Solicitud radio radio button Obligatorio: Académica, Comunitaria o Institucional.
Documento Adjunto file file Formatos autorizados: PDF, PNG, JPG (Límite estricto: 3 MB).
Descripción / Mensaje textarea Área de texto Obligatorio, descripción de la propuesta (hasta 2000 caracteres).

9.1. Flujo de Envío y Persistencia

  1. El usuario diligencia los campos en la vista ContactPage.jsx.
  2. El validador de cliente comprueba que no existan campos obligatorios vacíos ni archivos fuera de formato.
  3. Se genera un objeto FormData y se transmite vía POST /api/contact.
  4. El middleware multer inspecciona el archivo, lo renombra con UUID y lo almacena en backend/uploads/.
  5. El controlador contactController.js persiste la solicitud en MongoDB y retorna el submissionId.
  6. La interfaz despliega un banner animado de confirmación con el identificador generado en base de datos.

10. Guía de Instalación, Pruebas y Diagnóstico

10.1. Instrucciones de Despliegue Local Reproducible

# 1. Clonar el repositorio canónico
git clone https://github.com/mmorfe-engineer/uvm-4.3-jgh-proyecto-final.git
cd uvm-4.3-jgh-proyecto-final

# 2. Instalar dependencias de todo el monorepo
npm install && npm --prefix backend install && npm --prefix frontend install

# 3. Iniciar el motor persistente de MongoDB local (Puerto 27017)
npm run dev:db

# 4. En otra terminal, sembrar el administrador y encuestas iniciales
npm run seed:admin

# 5. Iniciar backend y frontend en desarrollo
npm run dev:backend   # Escucha en http://localhost:5000
npm run dev:frontend  # Escucha en http://localhost:3000

10.2. Ejecución y Resultados de Pruebas Automatizadas

El sistema cuenta con una suite integral ejecutada mediante npm test:

  • Pruebas de Backend (node:test + supertest): 16 pruebas automatizadas aprobadas (100% de éxito). Validan registro, unicidad de correo, login con cookies de sesión, denegación 401/403 (RBAC), publicación de encuestas, formulario de contacto multipart y rechazo de archivos ejecutables (.exe).
  • Pruebas de Frontend: Validación de compilación de producción con Vite, verificando la generación íntegra de `dist/index.html` y los bundles JavaScript y CSS.
